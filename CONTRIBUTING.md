# Contributing to TeamNexum projects

Thanks for helping! These rules apply to every TeamNexum repository. A repository can add its own `CONTRIBUTING.md` with setup steps and checks; when it does, read that one too.

## Workflow

1. Open or pick an issue, and assign yourself.
2. Create a branch from the default branch: `feat/<short-desc>`, `fix/<short-desc>`, `docs/<short-desc>` or `chore/<short-desc>`.
3. Keep commits small and focused, using [Conventional Commits](https://www.conventionalcommits.org): `feat(site): add the about section`.
4. Open a pull request that links the issue (`Closes #…`). At least one review is required before merging.
5. Never push directly to `main`.

## Before you open a pull request

- The project builds and its tests pass (see the repository README for the commands).
- The docs are updated if the behavior changed.
- No secrets, tokens or personal data are committed.

## Questions

Ask in the issue, or reach the team through the organization page.
